# 0027. Read a closed Zotero from a private copy of its database

Status: accepted (2026-10-26); applies 0006

## Context
ADR 0006 puts a read-only snapshot of `zotero.sqlite` second on the Zotero ladder, for when Zotero is closed (#14). Zotero uses WAL mode: transactions can remain in the WAL after a crash. Raw copies checked by timestamps, or even two equal reads, can mix pages from different transactions. A coordinated copy is required.

## Decision
- **Only when the local API does not answer.** A running Zotero is always read through its API. The copy is discarded if Zotero answers afterwards.
- **SQLite opens only the copy.** Raw handles exclude SQLite writers while the main database and WAL are copied. Any nonempty rollback journal fails with a reason to open Zotero; such journals can contain external super-journal paths that SQLite recovery would otherwise probe. On Unix a nonblocking exclusive POSIX record lock covers each main database. Obtaining it requires a writable descriptor, used only for locking and reads; read-only source permissions fail closed. Acquisitions inside Ibis are serialized because POSIX locks belong to the process. Main descriptors stay open without re-opening the same inode until copying ends. Windows read-only handles share only reads, excluding existing/new writers and deletion. Source file identity and metadata are rechecked. No source write, create, delete or chmod is attempted. A simultaneous Zotero launch may wait or fail until copying finishes, and can retry afterwards.
- **Local, private storage only.** Cached mount tables are classified before any path probes: bounded `/proc/self/mountinfo` on Linux and `/bin/df --libxo json -n -a -Y` using `getmntinfo(MNT_NOWAIT)` on macOS. Only known local filesystem types are eligible; FUSE, autofs, overlay, clustered and unknown types fail closed. Ambiguous non-ASCII aliases of unsupported mounts are refused conservatively. Symlink targets are classified before following them. Mapped remote drives, reparse/symbolic-link database files and dehydrated cloud files are refused before reads. Windows ancestor handles are held from root to leaf before descendant probes. Copies are made in a newly created owner-only directory (Unix mode 0700; a protected current-user-only Windows DACL set at creation using system Windows PowerShell/.NET). The caller guards and revalidates the Windows directory before copying. SQLite rebuilds `-shm` only beside the private copy. Normal completion removes the copy; crash leftovers remain private and are not deleted by a prefix match.
- **Known layouts and bounded work.** `userdata` schema versions 123–130 are checked by table and column. Missing selected libraries fail the whole candidate. Triggers, views and untrusted schema functions are off. One 60-second deadline and cancellation checks cover acquisition, SQLite, conversion and indexing; individual filesystem operations cannot be interrupted. Files are capped at 4 GiB, stored values at 1 MiB, inflated schema at 2 MiB. A cumulative 256 MiB allocation allowance covers schema rows, items, citation keys and a conservative conversion/index reserve before allocation. SQLite's internal process-wide heap is capped at 64 MiB, preserving any lower existing cap. Temporary query storage is forced to memory and checked, so no bibliography spills into an inherited or network temporary directory.
- **Zotero's own mapping.** The CSL type, field and creator mappings come from Zotero's stored global schema and its CSL export. Database and API input use one streaming mapper with the same duplicate diagnostics. Citation keys use Zotero's field, then Extra, then Better BibTeX's database, whose item key and library must match. A selected item relying on `better-bibtex/read-only.json` fails with a reason to open Zotero: that cache is written separately and cannot be coordinated through SQLite locks. Empty caches, unrelated rows and items with a usable native/Extra key do not block a read.
- **Content, not only timestamps.** The last accepted read retains source metadata and content digests. Every check reacquires/copies content before deciding conversion can be skipped; a same-size update within a coarse timestamp interval remains visible. Cached results include the references, so a discarded worker cannot suppress publication by advancing only a fingerprint.

## Consequences
- `rusqlite` with bundled SQLite (MIT; SQLite is public domain) is the one new dependency. `miniz_oxide` and `serde_json` already exist in the lockfile.
- Copies briefly need disk space equal to the database. Abandoned private copies need a future cleanup design that proves ownership; names and timestamps alone never authorize deletion.
- Windows requires its built-in Windows PowerShell 5.1/.NET helper; unavailable helpers fail closed.
- Each Zotero schema change needs synthetic coverage before widening the range. Real-Zotero CI compares the closed copy with the live API.
- Known rare export differences remain in `ibis_core::zotero::database`: EDTF dates/seasons, the local day of an access date, and item types without a CSL type.
