# 0027. Read a closed Zotero from a private copy of its database

Status: accepted (2026-10-26); applies 0006

## Context
ADR 0006 puts a read-only snapshot of `zotero.sqlite` second on the Zotero ladder, for when Zotero is closed (#14). Zotero uses WAL mode: transactions can remain in the WAL after a crash. Raw copies checked by timestamps, or even two equal reads, can mix pages from different transactions. A coordinated copy is required.

## Decision
- **Only when the local API does not answer.** A running Zotero is always read through its API. The copy is discarded if Zotero answers afterwards.
- **SQLite opens only the copy.** Unix opens source files read-only, binds sidecar opens to retained directory descriptors with `openat`, and enrolls directory and inode mutation witnesses before content reads (Linux inotify; macOS kqueue). Enrollment events are never reset. Passive `F_GETLK` queries reject existing SQLite lock ownership without taking a source-conflicting lock. A simultaneous Zotero launch must succeed during acquisition; mutations, watcher loss/overflow/revocation/errors, identity/presence changes or namespace replacement discard the candidate. Copy each complete WAL to its actual EOF first, then the main databases, then compare every source WAL byte and its EOF with the private WAL under the same deadline/cancellation. Keep the entire WAL: SQLite alone interprets recovery boundaries. Never copy source `-shm`. No source write, create, delete or chmod is attempted. Nonempty rollback journals fail before private SQLite opens: super-journal paths can otherwise escape the private VFS boundary.
- **Normal durable SQLite journals.** This guarantee assumes supported Zotero/Better BibTeX use normal durable WAL or rollback journaling; `OFF`/`MEMORY` journals are unsupported. It does not promise recovery from arbitrary raw/cloud failed-overwrite behavior outside that protocol. Windows is unfinished: its current deny-write handles can still interfere with startup. It cannot ship until handle-caching oplock acquisition, source file-ID binding and native delete/recreate/startup evidence pass; passive read oplocks alone are insufficient. All duplicated source handles must close before a deletion break is acknowledged.
- **Local, private storage only.** Cached mount tables are classified before any path probes: bounded `/proc/self/mountinfo` on Linux and `/bin/df --libxo json -n -a -Y` using `getmntinfo(MNT_NOWAIT)` on macOS. Only known local filesystem types are eligible; FUSE, autofs, overlay, clustered and unknown types fail closed. Ambiguous non-ASCII aliases of unsupported mounts are refused conservatively. Symlink targets are classified before following them. Mapped remote drives, reparse/symbolic-link database files and dehydrated cloud files are refused before reads. Windows ancestor handles are held from root to leaf before descendant probes. Copies are made in a newly created owner-only directory (Unix mode 0700; a protected current-user-only Windows DACL set at creation using system Windows PowerShell/.NET). The caller guards and revalidates the Windows directory before copying. SQLite rebuilds `-shm` only beside the private copy. Normal completion removes the copy; crash leftovers remain private and are not deleted by a prefix match.
- **Known layouts and bounded work.** `userdata` schema versions 123–130 are checked by table and column. Missing selected libraries fail the whole candidate. Triggers, views and untrusted schema functions are off. One 60-second deadline and cancellation checks cover acquisition, SQLite, conversion and indexing; individual filesystem operations cannot be interrupted. One running 4 GiB scratch-write budget charges actual bytes across all files and attempts, stored values at 1 MiB, inflated schema at 2 MiB. Before aliases are cloned, schema identifiers are restricted to 128 ASCII bytes, with at most 4096 bindings and 4 MiB of expanded storage. A cumulative 256 MiB allocation allowance covers schema rows, items, citation keys and a conservative conversion/index reserve before allocation. SQLite's internal process-wide heap is capped at 64 MiB, preserving any lower existing cap. Temporary query storage is forced to memory and checked, so no bibliography spills into an inherited or network temporary directory.
- **Zotero's own mapping.** The CSL type, field and creator mappings come from Zotero's stored global schema and its CSL export. Database and API input use one streaming mapper with the same duplicate diagnostics. Citation keys use Zotero's field, then Extra, then Better BibTeX's database, whose item key and library must match. A selected item relying on `better-bibtex/read-only.json` fails with a reason to open Zotero: that cache is written separately and is not a supported source of validated selected keys. Empty caches, unrelated rows and items with a usable native/Extra key do not block a read.
- **Content, not only timestamps.** The last accepted read retains source metadata and content digests. Every check reacquires/copies content before deciding conversion can be skipped; a same-size update within a coarse timestamp interval remains visible. Cached results include the references, so a discarded worker cannot suppress publication by advancing only a fingerprint.

## Consequences
- `rusqlite` with bundled SQLite (MIT; SQLite is public domain) is the one new dependency. `miniz_oxide` and `serde_json` already exist in the lockfile. Native witnesses use existing `rustix` and the already locked `nix` 0.31.3 through safe APIs; the direct edge supplies passive lock queries and macOS kqueue for #14.
- Copies briefly need disk space equal to the database. Abandoned private copies need a future cleanup design that proves ownership; names and timestamps alone never authorize deletion.
- Windows requires its built-in Windows PowerShell 5.1/.NET helper; unavailable helpers fail closed.
- Each Zotero schema change needs synthetic coverage before widening the range. Real-Zotero CI compares the closed copy with the live API.
- Known rare export differences remain in `ibis_core::zotero::database`: EDTF dates/seasons, the local day of an access date, and item types without a CSL type.
