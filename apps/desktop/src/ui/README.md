# Components and their states

The rules for each shared part, beside its code. The principles are in [design](../../../../docs/design.md) and the values every part reads in [foundations](../../../../docs/design/foundations.md).

Each component in `apps/desktop/src/ui/` wraps one React Aria component (decision 0021), owns one stylesheet that reads tokens only, and is the only way a screen draws that part. A screen needing a new control adds it to `ui/` with its line here first. Shared rules every window uses live in `ui/Foundation.css`.

**States change paint, never size** [C24]. Hover (`@media (hover: hover)` only), press, keyboard focus, selection and an open menu never move or resize anything: a part reserves the room for every state it can take (a chip's ×, a ring drawn inside), and `canvas/geometry.ts` sets each state on every control and fails any box that moves. A press gives a little (`--press-scale`, a transform, not layout) and springs back, as in [Motion](../../../../docs/design/foundations.md#motion). Disabled uses `--text-disabled` and stays focusable in menus. Busy shows a spinner after 400 ms with `aria-busy`. Invalid fields show words and an icon, never a red ring.

| | Pointer over it | Chosen or current | Keyboard focus |
| --- | --- | --- | --- |
| Result row | Quiet tint | `--selected` fill | The same fill; never a ring |
| Menu item | Menu highlight | Check in the leading column | Menu highlight |
| Segmented | Quiet tint | Darker thumb on a quiet track | Ring around the group |
| Buttons, pop-ups | One step darker | Primary: accent fill | Ring |
| Switch | No change | Accent track | Ring |
| Search field | None | None | The caret only |

- **Selection is a fill** [D7]: result rows use the full `--selected` fill with paired text, no side pill; a kept-open picker without focus dims it. Picture choices select as System Settings does: an accent ring outside the picture, following its corner, and a semibold caption.
- **Focus ring** [D8] only on keyboard focus: outside on controls, inside on rows (results, choice rows, sidebar), so no scroll area clips it. It hugs what it names, never the space around a control. Something only the app focuses (a sheet as it opens, a menu, anything with `tabindex="-1"`) never shows one (`canvas/geometry.ts`).

The Frame owns every notice (`LineNotice`, `ui/NoticeSlot`): it stands in for the heading (`FrameHeading`) at the same height, or, with no list, moves with its line to the room above an empty state (`FrameNotices`), drawn once so it keeps its state; it never adds a row, and no band is reserved empty. |

The search bar, a view's header and footer, the heading line, list headings and list rows are bands; a row is a band with a fill, which starts on the inset (a list holds the inset for its bands with `--band-inset`). A new part takes a band rather than computing a column with `calc()`. |

A screen fills its row's text, never its spacing or colours. |
| Sheet (`ui/Sheet`) | A view frame: its name as plain title text (a chip means "searching within", so only a view with a search has one), one body that alone scrolls, with its cards on the window inset and its words on the heading offset, and the footer as its action bar in the picker footer's words: leading actions, then the trailing ones with the primary last, then Back with Esc, each plain text as the footer's actions are. Quiet wherever its neighbours are quiet: in the search bar beside pin, and in a band that is itself a fill (the shelf's count); its chevrons say it opens, and its plate shows on hover and while open. |

## Menus

- [C9] In-window menus (library, the reference count, Form; the picker's format chooser and More are palettes) are `--r-large` frames padded `--space-1`, with `--r-control` rows at AppKit's item height (`--control-small-h`), separators and the shared overlay layer (`ui/Overlay`). A pop-up menu of choices is one narrow column whose rows name the choice and nothing more (15rem, Settings' default format menu); a quiet example shows only where names alone can't tell the choices apart, as in Show as (at most 20rem). Longer words (a style's full title, what a key format writes) are found by the filter, never drawn.
- A menu with any check keeps a leading check column for every row, so labels share one start and shortcuts line up at the end.
- **One heading** (`.ui-list-heading`) over a result list, a palette's group and a menu's section: small bold secondary type that never reads as an item, its words starting on the leading edge; a menu alone uses its items’ label column.
- Sections keep one order: what it is about, what you can do, Ibis itself. Labels name the result; a quiet example of the output sits on a second line under the label, as macOS menu subtitles do, in full up to the menu's width, never cut to a column.
- An unavailable choice stays in the list, dimmed, with why in a few plain words on that second line ("Only when cited alone"); it never sets the menu's width and never needs two lines.
- **A pop-up anchors to itself** [C21]: a pop-up that fills a form row (Show as) opens its menu under its own leading edge, at least as wide as the button, as `NSPopUpButton` does (a menu wider than the room left moves back only as far as the window's inset needs); toolbar pop-ups keep `bottom end`.
- **A menu's reason is a heading**, one line, never a paragraph. The format palette instead puts whose choice it is in `ViewFrame`'s footer status; its full explanation sits under the preview and describes the dialog.
- Menus over seven items get a filter field aligned with the labels. Header menus open `bottom end`, footer menus `top end`, flipping and shifting to stay within the window.
- Menus size to their labels up to the viewport and never wrap, as Mac menus; only at the window's edge does a label end in an ellipsis, its full name kept for screen readers. A scrolling menu ends on a whole row. Any pointer movement highlights an item.
- **More holds actions, not preferences**: the library (Show in Zotero or Open thesis.bib ⌘O, Show in Folder for a file, Choose Library…), this citation (Change Format…, Peek, Change Last Citation, Keep My Order, Cited Since Opening…, Forget Recent Citations) and Ibis (Keep Window Open, Keyboard Shortcuts, Settings…, Quit Ibis). Every action has its glyph on the tile column; a command's glyph and key come from the one table the `>` command list reads. Rows lives in Settings and the app's paste choices in the format chooser; each thing appears in one place.
